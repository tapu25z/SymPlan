\begin{abstract}
Mathematical reasoning with language models often relies on executable symbolic code. However, monolithic program synthesis requires simultaneously parsing problems, planning algebraic steps, and generating formal code, imposing severe cognitive load on compact small language models (SLMs, $\le 8\text{B}$ parameters). Under 4-bit quantization, compact models frequently exhibit semantic misformulation, omitted domain boundaries, and silent regressions during code repair. We introduce \textbf{SymPlan}, an inspectable neurosymbolic framework designed for resource-constrained models. SymPlan structures problem solving into three stages: (1) a bounded \textit{Fused Target-Anchoring Phase} ($\le 256$ tokens) establishing an immutable target anchor with a formal output signature and algorithmic roadmap; (2) \textit{Target-Anchored SymPy Code Generation} enforcing exact arithmetic and domain filters; and (3) \textit{Targeted Debugging with Anti-Regression Selection}, pairing static AST diagnostics with lexicographic ranking to prevent valid solutions from being overwritten. Across six open-weight models (3B--8B) on MATH-500 under 4-bit quantization, SymPlan outperforms monolithic SymCode by $+3.60\%$ to $+5.20\%$ (averaging $+4.20\%$) and Chain-of-Thought by $+12.64\%$, while raising the execution success rate to $89.90\%$ without fine-tuning.

\keywords{Neurosymbolic AI \and Small Language Models \and Mathematical Reasoning \and SymPy Code Generation \and Algorithmic Planning.}
\end{abstract}

\section{Introduction}

Mathematical reasoning in language models has advanced through Chain-of-Thought (CoT) prompting~\cite{wei2022cot} and structured search~\cite{wang2023selfconsistency,zhou2023leasttomost,wang2023plan}. Nevertheless, autoregressive generation often produces arithmetic errors, omitted steps, and unfaithful derivations that resist verification~\cite{lyu2023faithful,lightman2024verify}. Program-aided methods address these weaknesses by delegating computation to an external interpreter: PAL~\cite{gao2023pal} and PoT~\cite{chen2022pot} run numerical code in Python, MathCoder~\cite{wang2024mathcoder} and ToRA~\cite{gou2024tora} blend tool calls with rationales, and SymCode~\cite{nezhad2025symcode} uses SymPy~\cite{meurer2017sympy} for exact algebra.

However, program execution does not guarantee mathematical correctness: neurosymbolic frameworks fundamentally depend on whether the formalization faithfully represents the problem~\cite{lyu2023faithful,pan2023logiclm}. Most existing methods generate interpretation, planning, and code in a single prompt~\cite{gao2023pal,nezhad2025symcode}. Although frontier models often manage this combined task, compact small language models ($\le 8\text{B}$ parameters) under 4-bit quantization~\cite{dettmers2023qlora} degrade severely on MATH-500~\cite{lightman2024verify,hendrycks2021math}. In our experiments, these models exhibit four failure patterns:
(1)~\textit{Semantic misformulation:} the code solves a distorted or incomplete equation;
(2)~\textit{Target-anchor drift:} the program drifts from the queried objective and type signature, returning lists for cardinality or floats for fractions;
(3)~\textit{Domain boundary omission:} extraneous roots are accepted without filtering against domain bounds; and
(4)~\textit{Silent repair regression:} self-debugging yields valid scripts that replace previously correct answers with incorrect ones.

To address these issues, we present \textbf{SymPlan}, an inspectable neurosymbolic framework for compact models. SymPlan structures problem solving into three stages: first, a \textit{Fused Target-Anchoring Phase} establishes an explicit target anchor with the queried variable, formal output signature, and algorithmic roadmap ($\le 256$ tokens); second, a \textit{Target-Anchored Code Generator} translates this specification into self-contained SymPy code enforcing domain boundaries and exact arithmetic; third, a \textit{Targeted Debugging Loop} pairs tracebacks and AST diagnostics with an \textit{Anti-Regression Selection} mechanism to preserve valid intermediate solutions.

Our primary contributions are:
(1)~characterizing formulation, target-anchor drift, and repair failure modes across six compact models on MATH-500;
(2)~introducing SymPlan, uniting fused target anchoring, specification-guided SymPy synthesis, and anti-regression ranking; and
(3)~demonstrating that SymPlan outperforms SymCode by $+3.60\%$ to $+5.20\%$ (and CoT by $+12.64\%$) across six quantized SLMs, increasing ESR to $89.90\%$ without fine-tuning.

\section{Related Work}

\textbf{Program-Aided Reasoning.} PAL~\cite{gao2023pal} and PoT~\cite{chen2022pot} offload numerical steps to Python, MathCoder~\cite{wang2024mathcoder} and ToRA~\cite{gou2024tora} combine derivations with code execution, and SymCode~\cite{nezhad2025symcode} utilizes SymPy~\cite{meurer2017sympy} for exact algebra. However, monolithic generation overburdens compact models: if the model misinterprets equations or omits boundary conditions, the interpreter returns mathematically invalid answers.

\textbf{Formalization and Code Repair.} Faithful CoT~\cite{lyu2023faithful} separates reasoning from execution, and Logic-LM~\cite{pan2023logiclm} refines symbolic formulations via solver feedback. For code repair, Self-Debugging~\cite{chen2024selfdebug} iteratively revises scripts via interpreter feedback. On compact models, unanchored repair frequently induces code cycling or silent regressions. SymPlan grounds the repair process: the immutable target anchor preserves mathematical intent and output signature, while the attempt log prevents regressive overwrites.

\textbf{Planning in SLMs.} Structured prompting improves reasoning in compact architectures, including Self-consistency~\cite{wang2023selfconsistency}, Least-to-Most~\cite{zhou2023leasttomost}, and Plan-and-Solve~\cite{wang2023plan}. SymPlan builds on these insights by establishing an explicit target anchor and structured execution steps designed for quantized models.

\section{Method}
\label{sec:method}

\subsection{Framework Formulation}

Given a mathematical problem $q$, monolithic symbolic approaches~\cite{nezhad2025symcode} synthesize and execute code in a single unconstrained step: $C_{\text{base}} \sim \mathcal{M}(\cdot \mid q)$, $\hat{y} = \operatorname{Exec}(C_{\text{base}})$. On compact models, this joint generation causes semantic drift and execution crashes. SymPlan structures problem solving through three target-anchored phases:
\begin{align}
\mathcal{T} = (\tau, \Sigma, \mathcal{P}) &= \operatorname{FusedPlan}_{\mathcal{M}}(q), \label{eq:fused_plan} \\
C^{(0)} = \operatorname{CodeGen}_{\mathcal{M}}(q, \mathcal{T}), &\quad \mathcal{H} = \operatorname{ExecuteAndRepair}_{\mathcal{M}}(C^{(0)}, q, \mathcal{T}), \label{eq:codegen_repair} \\
\hat{y} &= \operatorname{SelectBest}(\mathcal{H}, \Sigma), \label{eq:select}
\end{align}
where $\tau$ denotes the queried target unknown, $\Sigma$ is the formal output signature, $\mathcal{P}$ represents the ordered computational plan, and $\mathcal{H}$ records the execution history. Like a holding anchor stabilizing team structure, establishing $\mathcal{T}$ prior to code generation anchors mathematical intent throughout subsequent execution and debugging.

\subsection{Fused Target Anchoring and Algorithmic Planning}

Multi-turn prompting pipelines often double autoregressive latency and cause context drift in compact models. To avoid this overhead, SymPlan extracts the target anchor and plan tuple $\mathcal{T} = (\tau, \Sigma, \mathcal{P})$ in a single bounded generation ($\le 256$ tokens):
(1)~\textbf{Target Specification ($\tau$):} the formal quantity queried, such as the positive real roots of an equation;
(2)~\textbf{Formal Output Signature ($\Sigma$):} a discrete type signature $\Sigma \in \{\text{numeric}, \text{text}, \text{tuple}, \text{set}, \text{symbolic}\}$, where queries asking ``how many'' assign $\Sigma = \text{numeric}$ to return set cardinality rather than enumerating values; and
(3)~\textbf{Computational Plan ($\mathcal{P}$):} an ordered sequence of symbolic operations $(p_1, \ldots, p_m)$ defining symbols, equations, transformations, and domain boundary checks.

\subsection{Target-Anchored SymPy Code Generation}

Given the target anchor and plan $(\tau, \Sigma, \mathcal{P})$, generator $\operatorname{CodeGen}_{\mathcal{M}}$ produces a self-contained SymPy script following four rules:
(1)~\textit{Exact Arithmetic:} Rationals use \texttt{sp.Rational(p, q)} or \texttt{sp.S(p)/q}; float evaluations via \texttt{evalf()} are excluded unless decimals are requested.
(2)~\textit{Domain Filtering:} Roots from \texttt{sp.solve} are filtered against domain bounds ($x \in \mathbb{R}^+$, non-zero denominators).
(3)~\textit{Simplification:} Expressions are simplified via \texttt{sp.together()} or \texttt{sp.cancel()}.
(4)~\textit{Signature Conformance:} The script emits a single boxed \LaTeX{} answer strictly conforming to signature $\Sigma$.

\begin{lstlisting}[style=promptstyle,language=Python]
import sympy as sp; x = sp.Symbol('x', real=True); eq = sp.Eq(sp.sqrt(x), x - 2)
cands = sp.solve((x - 2)**2 - x, x); valid = [s for s in cands if s >= 2 and eq.lhs.subs(x, s) == eq.rhs.subs(x, s)]
print(r"\boxed{%s}" % sp.latex(valid[0]))
\end{lstlisting}

\subsection{Targeted Debugging with Anti-Regression Selection}

Scripts execute in an isolated sandbox with timeout $\tau = 15$s and retry limit $K=2$, incorporating three safeguards:
\textbf{AST Diagnostics:} Tracebacks $e^{(i)}$ are paired with static AST diagnostics (\texttt{lint\_sympy\_code}) and candidate verification $v^{(i)}$.
\textbf{Anti-Cycling Repair:} If $C^{(i)} \equiv C^{(i-1)}$, an explicit constraint forces an alternative implementation strategy.
\textbf{Anti-Regression Ranking:} Every attempt is logged into history $\mathcal{H} = \{r_0, \ldots, r_k\}$ and scored via a lexicographic ranking tuple $\operatorname{Rank}(r) = \langle \mathbb{I}_{\text{exec}}(r), \mathbb{I}_{\text{valid}}(r), \mathbb{I}_{\text{verif}}(r), -\operatorname{attempt}(r) \rangle$, where $\mathbb{I}_{\text{exec}}$ indicates zero execution errors, $\mathbb{I}_{\text{valid}}$ denotes valid boxed extraction, $\mathbb{I}_{\text{verif}}$ indicates candidate verification pass, and $-\operatorname{attempt}(r)$ prioritizes earlier valid runs over speculative later mutations. The optimal record is $r^* = \arg\max_{r \in \mathcal{H}} \operatorname{Rank}(r)$. Multi-tier fallback handles unparseable outputs via regex scanning and type normalization.

\section{Experiments and Results}
\label{sec:experiments}

\textbf{Setup.} We evaluate on the full MATH-500 benchmark~\cite{lightman2024verify,hendrycks2021math} (7 subjects, 5 difficulty levels) across six open-weight models: Qwen2.5-3B-Instruct, Qwen3-4B, Qwen2.5-7B-Instruct, Qwen2.5-Coder-7B-Instruct, Llama-3.1-8B-Instruct, and Qwen3-8B. All models run under 4-bit NormalFloat4 (NF4) quantization~\cite{dettmers2023qlora} with greedy decoding ($\text{temp}=0.0$, $\text{max\_tokens}=1024$). We benchmark against Direct zero-shot generation, Chain-of-Thought (CoT)~\cite{wei2022cot}, and monolithic SymCode~\cite{nezhad2025symcode}, evaluating Accuracy (\%~EM) and Execution Success Rate (ESR).

\textbf{Stratified Analysis and Ablation.} Table~\ref{tab:stratified} indicates that gains concentrate in intermediate problems (Level 3: $+11.43\%$ on Coder-7B). By subject, improvements focus on \textit{Algebra} ($+9.67\%$), \textit{Counting \& Prob.} ($+13.15\%$), and \textit{Number Theory} ($+9.68\%$), where integer constraints are easily omitted by monolithic baselines. In component ablations, target anchoring ($+1.60\%$ to $+2.40\%$) and algorithmic planning ($+2.40\%$ to $+3.80\%$) each improve accuracy independently, while combining them with anti-regression ranking achieves the highest accuracy ($+3.60\%$ to $+5.20\%$).

\textbf{Error Diagnostics and Case Studies.} As detailed in Table~\ref{tab:error_breakdown}, SymPlan reduces total errors by 126 across 3,000 evaluations ($-8.5\%$ relative drop). Safe SymPy templates reduce runtime crashes by $37.5\%$, and formal output signatures reduce format mismatches by $23.5\%$. On a degree-5 interpolation problem with $p(n) = n/(n^2 - 1)$ for $n \in \{2,\ldots,7\}$, monolithic SymCode produced runnable code yielding 39690 instead of $3/56$ by omitting interpolation constraints; the target anchor in SymPlan registered all six points, enabling exact Lagrange reconstruction. Conversely, semantic misformulations remained flat ($974 \to 969$, $-0.5\%$), showing that neurosymbolic scaffolding resolves interface errors but cannot supply missing domain knowledge on complex non-constructive problems.

\section{Conclusion}

We presented SymPlan, an inspectable neurosymbolic framework for mathematical reasoning in compact models. By decoupling problem solving into fused target anchoring, specification-guided SymPy synthesis, and targeted debugging with anti-regression ranking, SymPlan resolves semantic misformulation, domain boundary omission, and repair regressions. Across six open-weight models (3B--8B) on MATH-500 under 4-bit quantization, SymPlan outperforms monolithic SymCode by $+3.60\%$ to $+5.20\%$ and CoT by $+12.64\%$, while raising execution success to $89.90\%$ without parameter updates. Future work will extend SymPlan to geometric diagrams and interactive theorem proving.
